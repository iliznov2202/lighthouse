# Регистрация и первый вход

Открыть `/register`. Последовательно создаются аккаунт, дата рождения, школа, класс, профиль и согласие с правилами. После регистрации показано приветствие с расписанием и домашкой; кнопка «Перейти в ленту» открывает `/demo`. В `/demo` также остаётся быстрый вход «Заглянуть в демо 9Б».

Данные для проверки:

- Школа: **ГБОУ школа №123, Санкт-Петербург**, класс **9Б**, 18 учеников.
- Приглашение: **MAYAK-9B-74**. Показывает подтверждение школы и класса, даже если ранее выбрана другая школа.
- Занятые username: `liza_n`, `sasha`, `anya`, `maxim`, `mayak`, `admin`.
- Тестовый вход `/login`: **sasha@mayak.demo / Mayak2026**. Новый локальный аккаунт также поддерживает повторный вход.

Возраст рассчитывается по реальной дате рождения и текущей дате в Москве, включая день рождения. До 14 лет доступен только отдельный экран ограничения; аккаунт не создаётся. На дате рождения заранее не показывается возрастная граница. Невозможные и будущие даты отклоняются.

Поля сохраняются при переходах назад. Приветствие восстанавливается после перезагрузки; возврат к профилю обновляет тот же аккаунт. После первого входа локально сохранены профиль, школа, класс, расписание и четыре задания. Фото аватара уменьшается до 256×256 и сохраняется локально. Принятие правил обязательно. Документы и восстановление доступа — демонстрационные интерфейсы.

## Структура

`src/features/onboarding/` содержит отдельные компоненты шагов, `OnboardingFlow.tsx`, контроллер `useOnboarding.ts`, сущности `types.ts`, данные `mock.ts`, проверку полей `validation.ts`, подготовку аватара `avatar.ts` и mock-адаптер `service.ts`.

Контракт `OnboardingGateway` отделяет компоненты от проверки email/username, приглашений, регистрации и входа. Для будущего API заменить адаптер; интерфейс не вызывает backend или реальные сервисы.

Локальные ключи: `mayak-mock-accounts-v1` — тестовые аккаунты с солью и SHA-256 отпечатком пароля; `mayak-registration-pending-v1` — аккаунт на экране приветствия; `mayak-mock-user-v1` — текущий пользователь. Это имитация авторизации, не механизм серверной защиты. «Начать демо заново» очищает данные регистрации вместе с демо.

## Проверка

`npm test -- tests/registration.spec.ts` проверяет весь путь, аватар, повторный вход, возрастную границу, неверные даты и поля, приглашения, пропуск профиля, занятые email/username, состояния загрузки, согласие, возврат после перезагрузки и ошибки локального хранилища. Сценарии запускаются на мобильном и desktop; дата тестов фиксирована на 1 октября 2026 года. Скриншоты сохраняются в индивидуальный каталог результата Playwright.

Для проверки готовой сборки запустить `npm run build`, затем `npm run preview -- --port 5174 --strictPort`. В отдельном терминале PowerShell задать `$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:5174'` и выполнить тесты. При заданном URL Playwright использует уже запущенный сервер. По умолчанию тесты запускают или используют dev-сервер на 5173.
