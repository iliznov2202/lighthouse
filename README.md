# Маяк

## Мобильное приложение и установка

В мобильной версии текст постов и комментариев — 16 px, основные кнопки имеют зоны нажатия от 44 × 44 px. Комментарии, реакции и короткие действия открываются нижними панелями; публикация, домашка и импорт расписания — отдельными экранами с учётом экранной клавиатуры. Разделы сохраняют позицию прокрутки, публикации и комментарии — черновики на устройстве. Удаление своей публикации можно отменить в течение восьми секунд; очистку черновика — до закрытия формы.

Все 22 стикера обновлены: локальные SVG с персонажем-маяком. Исходники находятся в `src/design/stickers/`, генератор — `scripts/create-stickers.mjs`.

PWA работает в production-сборке через HTTPS или localhost. Manifest, PNG-иконки и service worker публикуются вместе с `dist`; пути учитывают `VITE_BASE_PATH`. После загрузки и кэширования приложение открывается без сети. Состояние остаётся локальным, синхронизация и push-уведомления не подключены. Обновление устанавливается по кнопке «Обновить», без внезапной перезагрузки формы.

В профиле есть установка на Android и инструкция для iPhone: Safari → «Поделиться» → «На экран Домой». На устройстве установленное приложение запускается сразу в демо.

Проверка production-сборки, офлайн-перезагрузки и публикации без сети:

```powershell
$env:VITE_BASE_PATH='/lighthouse/'
npm run build
node scripts/verify-mobile.mjs
```

Скрипт использует установленный Chrome, поднимает временный локальный сервер и сохраняет мобильные скриншоты в `artifacts/mobile-refresh-*.png`.

**Зажги свой Маяк. Играй. Создавай. Приноси очки своей школе.**

Маяк — проект для школьников: квизы, мини-игры, творческие конкурсы и общие победы класса и школы. Главная страница — интерактивный frontend MVP знакомства с проектом. Backend к лендингу не подключён.

Существующий прототип школьного приложения сохранён отдельно по адресу `/demo`.

## Интерактивный лендинг

- `/` — море, остров и SVG-маяк, плавные волны, параллакс, три игровых задания, цепочка «Ты → Класс → Школа → Регион», карточки активностей и демонстрационный рейтинг.
- «Зажечь маяк» запускает состояния `initial → quiz → stars → interests → completed` без перехода на другую страницу. Неверный ответ можно исправить; три звезды появляются в случайных позициях, интересы поддерживают множественный выбор. Каждая искра зажигает отдельный элемент маяка.
- После завершения показываются условные +30 очков и переход к созданию профиля. При переходе в регистрацию в той же сессии виден бонус. Игра хранится только в памяти, при перезагрузке сбрасывается; в реальный рейтинг очки не записываются.
- `/register` и `/login` открывают регистрацию и вход приложения. Регистрация проходит через аккаунт → дату рождения → школу → класс → профиль → правила → приветствие → ленту. Работают поиск школы, приглашения, необязательный аватар, проверка username, обязательное согласие и возрастная граница 14 лет. Mock-аккаунт сохраняется только в браузере; повторный вход проверяет локальные данные. Пароль в открытом виде не сохраняется, запросов к backend нет. Восстановление доступа показывает тестовое сообщение без отправки письма.
- `/about`, `/rules`, `/privacy`, `/terms`, `/support` — информационные и placeholder-страницы. Юридические документы этих маршрутов ещё не опубликованы.
- Все изображения и шрифты локальные. Интерфейс адаптирован к desktop/tablet/mobile, поддерживает клавиатуру и `prefers-reduced-motion`.

Лендинг разбит на компоненты в `src/landing/`: `Header`, `Hero`, `Lighthouse`, `MiniGame`, `QuizGame`, `StarGame`, `InterestGame`, `GameProgress`, `GameComplete`, `Features`, `Activities`, `SchoolRanking`, `FinalCallToAction`, `Footer`. `useMiniGame.ts` управляет состояниями и очищает таймеры; `router.tsx` поддерживает маршруты, ссылки и историю браузера. Данные рейтинга остаются локальными примерами; технические подписи mock/demo убраны из блоков лендинга.

Лендинг использует дизайн приложения: `styles.css`, `theme.css`, `colors.css`, токены `--primary`, `--navy`, `--border`, `--radius`, общий `ThemeProvider` и иконки `src/design/icons.tsx`. `Brand`, `Lighthouse`, `Avatar`, `Tag` переиспользуются из `components/ui.tsx`. Общие `ActivityCard` и `RankingRow` применяются и в лендинге, и в «Битве классов». `landing.css` отвечает за раскладку и декорации, собственной палитры у лендинга нет. Регистрация и вход используют существующий `features/onboarding`, отдельная копия auth-форм удалена.

Переходы заданий занимают 150–220 ms, подсветка маяка — 300 ms; финальный луч проходит по экрану. Звёзды имеют target 64×64 px и отступы от края, счётчик вынесен за игровую область. Прогресс доступен как `progressbar`, заголовок получает фокус после смены задания. При reduced motion анимации отключаются. Финальный CTA возвращает к игре, а после завершения открывает регистрацию. Карточка первого достижения и +30 — preview, без записи в школьный рейтинг.

*Демо приложения `/demo` сохраняет прежние ленту, расписание, домашку, квиз и настройки. Его AI-ответы, дайджесты и обработка фото демонстрационные; изменения демо сохраняются локально в браузере. Код приложения и стили его отдельных модулей загружаются при открытии `/demo`, `/register` или `/login`; общие стили и тема доступны уже на лендинге.*


## Запуск frontend

React + TypeScript + Vite. Требуется Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
npm run build
npm test
```

Открыть http://127.0.0.1:5173/ — лендинг. Прежний интерфейс — http://127.0.0.1:5173/demo, затем «Заглянуть в демо 9Б». Браузер для Playwright устанавливается командой `npx playwright install chromium`. Для установленного Chrome можно передать `PLAYWRIGHT_CHANNEL=chrome` (PowerShell: `$env:PLAYWRIGHT_CHANNEL='chrome'`).

Проверка только лендинга: `npm test -- tests/landing.spec.ts`. Тесты проходят три задания, регистрацию в приложение, CTA, историю, прямые маршруты, клавиатуру и светлую/тёмную тему. Ширины: 320/375/390/430/768/1024/1280/1440/1920 px. Дополнительно вся игра проверяется на телефонах высотой 664 px. Скриншоты сохраняются в `artifacts/landing-*.png`. Backend для этих тестов не нужен.

Проверка готовой production-сборки без HMR: `npm run build`, затем `npm test -- --config=playwright.preview.config.ts tests/landing.spec.ts`. Playwright запускает Vite preview на `http://127.0.0.1:4174` и сохраняет результаты отдельно в `test-results-landing/`. Убрать имя файла из команды, чтобы проверить весь frontend на production-сборке.

Для статического хостинга все неизвестные пути (`/register`, `/login` и другие) должны возвращать `index.html`; Vite dev/preview уже поддерживает SPA fallback. Для размещения в подкаталоге задать `VITE_BASE_PATH=/path/` при сборке.

## Проверка «Битвы классов»

Карточка в ленте открывает 10 вопросов. За правильный ответ начисляются 100 личных очков и 1 очко классу. При результате 8/10 класс 9Б переходит с 4-го на 3-е место: 157 → 165 очков, до 8Б остаётся 6. Другие результаты дают реальное количество очков по ответам.

Результат → рейтинг → «Классы / Ученики». «Поделиться результатом» и «Позвать одноклассников» открывают подготовленные карточки и текст. В «Все школы» показано состояние будущей функции.

Кнопка «Демо события» на экранах квиза, результата и рейтинга переключает активное событие, последние 24 часа и итоги. Итоги используют отдельный подготовленный рейтинг: 10А / 9Б / 8Б. Личный результат остаётся фактическим. В завершённом событии нельзя отвечать. Даты зафиксированы для демонстрации; реального таймера и push нет.

Попытка сохраняется при уходе и перезагрузке, повторное открытие результата не начисляет очки. После завершения создаётся один системный пост в школьной ленте. Сбросить попытку и данные можно в профиле через «Начать демо заново».

## Данные и интерфейс

- `src/features/competition/types.ts` — Quiz, QuizQuestion, QuizResult, CompetitionEvent и сущности рейтинга.
- `src/features/competition/mock.ts` — вопросы, событие, начальный и итоговый рейтинг, сообщения события.
- `src/features/competition/logic.ts` — проверка ответов, очки, позиции, разница с соседним классом; правила берутся из события.
- `src/features/competition/useCompetition.ts` — локальная попытка по идентификатору события и защита повторного прохождения.
- `src/features/competition/Competition.tsx` — карточка, прохождение, результат, рейтинг и демо-состояния.
- `src/theme.css` — читаемая типографика, плавающая навигация, панели создания; Inter поставляется локально, на Apple используется системный шрифт.
- `src/components/PostComposer.tsx` и `SocialPost.tsx` — опросы, сменяемые реакции, до трёх фотографий с просмотром.

Изменения демо-frontend хранятся локально в браузере. Фотографии постов уменьшаются и сохраняются как data URL; фотографии для демо-распознавания не отправляются и не сохраняются. Отдельный backend находится в `backend/`; подключение frontend к API и синхронизация пока не реализованы. Команды запуска, миграции, seed и REST endpoints описаны в [backend/README.md](backend/README.md).

Колокольчик в шапке открывает окно последних уведомлений с вкладками «Все / Учёба / Общение», счётчиками и отметкой прочитанных. «Посмотреть все уведомления» открывает полный список. Клик по событию отмечает его прочитанным и открывает связанный экран; окно закрывается повторным нажатием на колокольчик, кликом снаружи или Escape. Прочтение сохраняется локально.

Лента поддерживает порядок «Свежее / Популярное / Обсуждаемое»; выбор сохраняется на устройстве. Закрытие поиска сбрасывает запрос. Черновик публикации сохраняет текст, опрос, фото, стикер, аудиторию и анонимность; восстанавливается при повторном открытии и после перезагрузки. После публикации или очистки черновик удаляется, при ошибке публикации остаётся доступным. Панель комментариев прокручивает ветку отдельно от закреплённого поля ответа. Мобильные поля используют 16 px, а панели учитывают доступную высоту через Visual Viewport.


## Иконки и стикеры

Функциональные иконки — [Lucide](https://lucide.dev/), через единый модуль `src/design/icons.tsx`: 24×24 px, обводка 2,5 px, скруглённые линии, без заливки во всех состояниях. Размеры закреплены в `src/design/visuals.css`. Предметы и реакции используют этот же набор.

22 стикера из корневой папки `stickers/` подключены через `src/design/stickers.ts`. Исходники сохранены, Vite включает их в production-сборку. Стикеры используются в оформлении и доступны в редакторе публикации: «Стикеры» → выбрать → «Опубликовать». Пост со стикером можно публиковать без текста и фото; выбор сохраняется локально вместе с публикацией.

Компонент `Sticker.tsx` скрывает декоративные изображения от скринридера; у опубликованного стикера есть текстовое описание. Логотип и иллюстрированные аватары остаются отдельными графическими элементами.
